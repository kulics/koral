# api/ — API 文档（生成物）

`api/` 下的页面**全部由 `toolchain/doc` 生成**，记录 `std/` 的公开 API 签名。
手改生成页会在下次生成时被覆盖，且会让 `--check` 报 STALE。

## 布局

```
api/
  README.md      本文件（手写，不要放进 std/）
  std/           生成页，一个模块一页
    std.md       模块 Std
    io.md        模块 Std.Io
    async.md     模块 Std.Async
    ...          共 14 个模块
```

将来若有别的包的 API 页，落 `api/<包名>/`，一个包一个叶子目录。

## ⚠ 为什么 README 不在 `std/` 里

生成器写页前会 **`clear_generated_docs`：递归删掉输出目录下所有 `.md`**，再重写
（`toolchain/doc/generate_std_api_docs.koral:457-480`）。输出目录是生成器独占的叶子。

所以：

- **`api/std/` 里只能放生成页。** 放进任何手写文件，下次生成就被删掉。
- **`api/README.md` 必须留在 `std/` 上一层。** 若有人把生成器的输出目录「简化」成 `api/`，
  这份 README 会在下次生成时被静默删除。

## 怎么再生成

```bash
bin/toolchain-doc-gen/koral_doc --self-test   # 生成器自检
bin/toolchain-doc-gen/koral_doc               # 重新生成 14 页
bin/toolchain-doc-gen/koral_doc --check       # 过期闸门
```

`--check` 把磁盘上的页与生成器当前输出**逐字节**比对，不一致就报
`STALE: <path> does not match what the generator would write` 并退出非零。
它就是「API 页是否过期」的判据。

**顺序要紧**：改了生成器的输出文本后必须**先重新生成再 `--check`**，否则必红。
另外 `bin/` 是 gitignore 的，克隆后要先构建 `koral_doc` 再跑 `--check`——拿旧二进制跑会误报。

## 什么算「API 变了」

改 `std/` 的公开声明（签名、默认参数、可见性、新增/删除成员）后，重新生成并把 14 页一并提交。
`--check` 会在 CI 之外的 checklist 里被要求跑过。

生成页顶部有机器可读标记：

```
<!-- GENERATED by toolchain/doc. Do not edit by hand. ... -->
```

看到这个标记就别手改。
